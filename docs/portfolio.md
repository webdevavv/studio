# Портфолио

`/portfolio` — серверная галерея. GET-параметры `category` и `type` читаются из асинхронного `searchParams`, принимаются только существующие значения. Пустые категории и типы не выводятся: варианты вычисляются из опубликованных проектов. Неизвестные и повторяющиеся параметры игнорируются; несовместимые фильтры показывают состояние без результатов и ссылку сброса. Форма работает без JavaScript.

`/portfolio/[slug]` — разбор проекта: задача, решение, изображение интерфейса, состав разделов, особенности разработки, результат, связи с услугами, ценами, каталогом и заявкой. Для будущих клиентских проектов отдельно выводится блок «О клиенте» с подтверждённым названием и объёмом. Страницы используют `generateStaticParams`, неизвестный slug вызывает `notFound`. У галереи и каждого разбора отдельные title, description, canonical и Open Graph. Предпросмотр не дублируется: ссылка ведёт на существующую страницу каталога.

## Источники и статус

BEAUTY SHE, «Золотые ручки» и Notimo имеют статус `demo`. Название «Золотые ручки» взято из `src/lib/catalog.ts`. Названия, категории, изображения и URL берутся из опубликованного каталога, описания разбора опираются на его `description`, `fullDescription` и `includedFeatures`. Внешние демо не являются доказательством клиентского заказа, работоспособности интеграций или результатов бизнеса. В тексте нет вымышленных клиентов, сроков, метрик и цен.

Сайты салона и школы-студии отнесены к типу `business-card` как презентации бизнеса, Notimo — к `landing-page` как презентация одного продукта. Это классификация структуры, не утверждение о заказанных услугах.

## Добавление реального кейса

Источник данных — `src/lib/portfolio.ts`, экспорт `portfolioProjects`, поиск — `getPortfolioProject(slug)`. Подтверждённые клиентские работы добавляются в отдельный массив `clientProjects`, независимо от шаблонов каталога; сейчас массив пуст. `PortfolioProject` — объединение demo/client. Для `status: 'client'` обязательны `confirmedFacts`: согласованное название клиента, объём, результат и внутренний источник подтверждения `evidence`. Источник не выводится на публичную страницу. Каждое публичное утверждение, включая результат и описания разделов, должно быть подтверждено; при отсутствии подтверждения сохраняется demo-статус.

Общие поля: slug, title, categoryId/category, siteType, task, solution, developmentFeatures, description, image, demoUrl, sections, result, seoTitle/seoDescription. `catalogSlug` необязателен: при наличии ведёт к интерактивному просмотру каталога. Для реального проекта `confirmedFacts.scope` и `confirmedFacts.result` выводятся шаблоном. Не добавляйте показатели, отзывы, сроки или цены без отдельного подтверждения.

## Дизайн

Прочитаны проектный taste-skill, существующая direction sheet `.taste-skill/direction.json` и документация установленного Next.js по page, metadata и generateStaticParams. Сохранены существующие токены, типографика и мягкие углы студии. Основной материал — крупные реальные изображения интерфейсов; карточки представляют последовательность проектов с пояснениями. Единственное управление галереи — доступные GET-фильтры. Анимаций и новых зависимостей нет.

## Проверка

`npm run typecheck` и `git diff --check` прошли. До уточнения финального SEO-заголовка и добавления секций подхода/процесса в Chrome проверены `/portfolio` и `/portfolio/notimo` на 390, 768 и 1440 px: горизонтального переполнения нет, все изображения загружаются. Сняты и просмотрены скриншоты; для полного снимка страницы lazy-изображения предварительно прокручены в область просмотра. Фильтр `category=technology&type=landing-page` возвращает только Notimo; `category=technology&type=business-card` показывает пустой результат. Неизвестный slug возвращает HTTP 404. Финальная визуальная проверка и общий production build выполняются отдельно владельцем интеграции.
