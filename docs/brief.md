# Форма заявки и заготовка YouGile

Главная использует обычную форму `ContactForm` в `/#contacts`. Старый якорь `/#brief` сохранён для входящих ссылок, но чат, вопросы по шагам, история, рекомендации и скачивание брифа удалены.

## Данные и интерфейс

Поля: тип сайта (новый, шаблон, нужна помощь), способ связи (Telegram, MAX, звонок), обязательный телефон и необязательный комментарий до 1500 знаков. Дополнительные контакты и название компании не требуются. Телефон проверяется на клиенте и сервере. Согласие не предустановлено; ссылка берётся только из настройки действующей политики.

Пока конфигурация отсутствует, форма показывает, что заявки не принимаются, и не отправляет данные. Никаких фиктивных подтверждений. При подключении доступны состояния отправки, подтверждённого успеха, отказа и неопределённого результата. Данные не попадают в localStorage или аналитику.

## Сохранённый API

`POST /api/brief` сохранён для существующей интеграции. Новый контракт:

```json
{
  "id": "UUID v4",
  "answers": {
    "route": "Готовый шаблон",
    "channel": "Telegram",
    "phone": "+7 999 123 45 67",
    "comment": "Комментарий о проекте"
  },
  "consent": true,
  "website": ""
}
```

`website` — скрытая ловушка для автоматического заполнения. Сервер принимает только разрешённые поля, проверяет варианты выбора и телефон, Origin, JSON, размер до 40 КБ и согласие. HTML-текст перед включением в описание задачи экранируется.

Адаптер сохраняет существующий `POST {YOUGILE_API_URL}/tasks`, Bearer-авторизацию, `columnId`, необязательное назначение менеджера, `completed: false`, `archived: false`. В карточке: выбранные сайт и канал, телефон, комментарий, ID, время, источник, согласие и следующий шаг менеджера. Ключи остаются на сервере.

## Подключение на следующем этапе

Настройки `brief-config.ts` и имена переменных сохранены:

```dotenv
BRIEF_ENABLED=true
YOUGILE_API_URL=https://yougile.com/api-v2
YOUGILE_API_KEY=ключ_сервера
YOUGILE_COLUMN_ID=uuid_колонки
YOUGILE_ASSIGNED_ID=uuid_менеджера
BRIEF_POLICY_URL=https://ваш-домен.ru/privacy
```

Нужны настоящая действующая политика, ключ, колонка и при необходимости менеджер. На этом этапе реальные значения не задавались и заявки в CRM не создавались. После изменения настроек пересоберите и перезапустите приложение: главная рендерится статически. При подключении проверьте одну согласованную тестовую карточку и её назначение в вашем экземпляре YouGile.

## Доставка и ограничения

- Защита от двойного клика в UI; успех блокирует повторную отправку.
- Один ID сохраняется при повторе неизменённой заявки. Сервер объединяет параллельные запросы с одинаковым ID на 30 минут и отклоняет изменение содержимого под тем же ID.
- Определённый отказ CRM допускает повтор. При таймауте или ошибке сервера CRM исход неизвестен: ID остаётся заблокирован, UI просит уточнить получение перед повтором.
- Ограничение: 3 попытки на телефон за 10 минут, до 500 записей дедупликации. Таймаут YouGile — 15 секунд, клиентского запроса — 20 секунд.
- Дедупликация и лимиты используют память одного процесса. Перед несколькими экземплярами или serverless нужно общее хранилище с TTL; для публичного приёма также лимит на хостинге/reverse proxy. Эти эксплуатационные настройки остаются частью подключения.
- Персональные данные не записываются приложением в логи. Во время TTL заявки находятся в памяти сервера.

## Проверки

`tests/brief.spec.ts` проверяет контракт, экранирование, отключённую конфигурацию, валидацию, honeypot, ограничение размера, дедупликацию, отказ, неопределённый результат и лимит попыток. YouGile подменяется тестовой функцией; реальные заявки не создаются.

Два браузерных сценария включённой формы запускаются с `TEST_REQUESTS_ENABLED=true` против локальной сборки с тестовой конфигурацией. Они перехватывают `/api/brief` и проверяют согласие, выбранные поля, успех, сохранение данных и блокировку повторов. Обычный запуск без конфигурации явно пропускает только эти два сценария.
