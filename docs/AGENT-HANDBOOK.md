# Сайтика: справочник для агента

Актуально на 1 ноября 2026 года. Прочитать перед изменениями сайта вместе с AGENTS.md. Исходный код и последующие указания владельца имеют приоритет. Обновлять этот файл при изменении услуг, цен, страниц или общих компонентов.

## Продукт и условия

Сайтика — веб-студия для малого бизнеса и частных специалистов по России. Основной сценарий: выбрать формат или демо → изучить условия → отправить заявку → согласовать работу.

| Услуга | Цена и смысл |
| --- | --- |
| Готовый сайт из каталога | Сейчас опубликованные шаблоны по 2 000 ₽. Замена текстов, изображений, логотипа и контактов в существующем дизайне и структуре. Источник конкретной цены — catalog.ts. |
| Индивидуальный лендинг | 10 000 ₽ за согласованный объём. Одна страница под одно предложение. Не писать диапазон 7–10 тысяч. |
| Сайт-визитка | По задаче: стоимость согласуется по страницам, материалам и функциям. Не публиковать неподтверждённую фиксированную цену. |

В site.ts остался старый массив services с ценой визитки 19 900 ₽: это не утверждённый публичный тариф текущих коммерческих страниц. Не переносить его в новые тексты без уточнения владельца.

До двух дней — условный срок типового проекта после согласования объёма, получения готовых материалов и предоплаты, с подтверждённой датой старта. Не обещать безусловные два дня.

Оплата: предоплата до разработки, остаток после демонстрации, согласованных правок и приёмки. Проценты не установлены. Передача файлов и инструкции запуска после полной оплаты. Включён один общий пакет клиентских правок в согласованном объёме; ошибки исполнителя исправляются отдельно от него. Новые задачи оцениваются отдельно.

Домен и хостинг оформляются на клиента. Тарифы провайдеров, регистрация и продление оплачиваются отдельно. Размещение сайта — отдельная разовая услуга; не путать с тарифом хостинга.

## Страницы

- `/`: главный экран с превью на устройствах, аргументы, форматы сайтов, демопроекты, цены, подход, процесс, FAQ, заявка. На ПК форматы представлены компактными текстовыми карточками без превью: номера, крупные названия, тёмный акцент на лендинге. Галерея демопроектов — три компактные карточки в ряд. На мобильном обе подборки остаются слайдерами. Блок «О студии» скрыт на мобильном.
- `/services`: услуги, выбор лендинга/визитки, состав разработки, процесс, четыре примера, FAQ, заявка.
- `/services/landing-page`: оформление как у визитки; схема блоков одной страницы, примеры, состав работ, цена 10 000 ₽, сравнение форматов, шесть этапов, FAQ и форма.
- `/services/business-card`: схема страниц с переходом к заявке, примеры, список включённых работ, расчёт стоимости, сравнение форматов, шесть этапов, FAQ и форма.
- `/prices`: три компактные карточки (название, цена, описание, «Заказать»), сравнение, факторы стоимости, допуслуги, порядок оплаты, объяснение доступной цены, FAQ и форма.
- `/catalog`: поиск/фильтры готовых дизайнов, карточки, стандартная настройка и отдельные работы, процесс.
- `/catalog/[slug]`: детали шаблона, интерактивный просмотр на устройствах, условия, форма заказа.
- `/portfolio`: фильтры, карточки демопроектов с демо и разбором, принципы качества, выбор готовой основы/индивидуальной разработки, этапы и форма.
- `/portfolio/[slug]`: разбор задачи, интерфейса, решений и демонстрационного результата.
- `/blog`: поиск, тема, сетка 3/2/1 колонки, 12 статей на страницу, нумерация; вся карточка кликабельна.
- `/blog/[slug]`: статья с оглавлением и связанными материалами.
- `/privacy`: подробная политика обработки данных; `/consent`: отдельный текст согласия. Реквизиты ИП и email оставлены явными полями по просьбе владельца: документы требуют заполнения перед использованием. Состав данных сверять с brief.ts, сроки хранения и расположение инфраструктуры подтвердить у владельца. Ссылки есть под обеими формами и в общей навигации подвала.
- Мобильный пункт каталога сохраняет тёмный текст на оранжевой поверхности и при aria-current; не переопределять его общим акцентным цветом активной ссылки.

## Дизайн и мобильная версия

Цвета: ink #132938, paper #edf5f8, sky #b7ddf3, surface #deecf3, accent #ff6b35. Шрифт Golos Text, локальные файлы в public/fonts. Использовать существующие карточки, кнопки и скругления. Не добавлять маркеры-выделители и случайный декор: владелец предпочитает тёмные/голубые поверхности и оранжевые слова.

Текстовые ссылки: плавный оранжевый hover без фона. Отдельные ссылки имеют SVG-стрелку, ссылки внутри предложений — без стрелки. Не использовать emoji-стрелки. На тёмном фоне проверять контраст, общие CSS-правила могут перебить цвет.

На мобильном (обычно до 760px): небольшие боковые поля, без двойного вложенного padding. Общие поправки — `src/app/mobile-spacing.css`. Сохранять отступы у списков, номеров и элементов управления.

`MobileCardSlider`: свайп и кликабельные точки, без стрелок; состояние по scroll. На ПК обычная раскладка. Используется в форматах/проектах главной, настройке каталога, включённых работах/примерах услуг и принципах портфолио. На мобильном не анимировать появление слайдов. В некоторых блоках виден край следующего слайда. Не менять высоту при листании, использовать stretch. Для мобильного правового пункта предусмотрен сокращённый текст.

Мобильное меню: бургер справа, полноэкранное плавное раскрытие, Escape, ограничение фокуса, блокировка прокрутки. «Каталог» скрыт в мобильной шапке и выделен оранжевым первым пунктом меню. На ПК каталог остаётся в шапке. Сообщение менеджера в процессе услуг скрыто на мобильном.

Мобильное сравнение цен — настоящая горизонтальная таблица со sticky первой колонкой, около 500px высотой. Не превращать её обратно в вертикальные карточки.

## Заявки и инфраструктура

Next.js App Router, React, TypeScript. Требование Node: смотреть package.json (сейчас >=24 <25). Next.js этой версии имеет отличия: перед реализацией читать локальную документацию node_modules/next/dist/docs.

`ContactForm` и `TemplateRequestForm` отправляют `/api/brief`. Серверная интеграция YouGile, конфигурация `src/lib/brief-config.ts`, контекст `src/lib/request-context.ts`. Сохранять валидацию телефона, защиту от спама, согласие и контекст source/service/projectSlug/pageUrl. При проверках не отправлять реальные тестовые заявки в CRM.

`.env.example` описывает настройки. API-ключи только серверные, никогда NEXT_PUBLIC и никогда в Git. Форма включается только с BRIEF_ENABLED=true, ключом, колонкой, корректными HTTPS URL API и политики. Индексация по SITE_INDEXABLE; в разработке false. Продакшн URL из NEXT_PUBLIC_SITE_URL. Проверять реальные env-настройки отдельно, не считать публикацию настроенной по наличию кода.

## Проверки и Git

- `npm run typecheck`, `git diff --check` после изменений.
- `npm run blog:check`, `npm run test:blog` для материалов/блога.
- `npm run build` для итоговой сборки.
- `npm test` — Playwright; старые проверки UI могут требовать обновления под новые карточки/combobox. Проверять смысл, не удалять тесты ради зелёного статуса.
- Ручная/браузерная проверка 320, 375, 768, 1440px: overflow, меню, свайп/точки, фильтры, якоря и клавиатура. Не останавливать пользовательский dev-сервер 3000.
- next-env.d.ts генерируется Next: dev может менять пути на .next/dev/types. Не коммитить шумовые dev-пути; сборка восстанавливает .next/types.
- Remote origin: https://github.com/webdevavv/studio.git. Не публиковать на хостинг без запроса. Не коммитить секреты, node_modules, .next и временные скриншоты.

Дополнительные подробности: docs/brief.md, docs/catalog.md, docs/portfolio.md, docs/request-context.md, docs/blog.md. Старые отчёты о дизайне и проверках описывают состояние на момент создания; тарифы и текущий UI сверять с этим файлом и кодом.
