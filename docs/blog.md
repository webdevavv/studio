# Как добавлять статьи в блог

## Самый быстрый способ

1. Подготовьте статьи в формате **`.md`, кодировка UTF-8**. В начале каждого файла добавьте шапку из примера ниже.
2. Скопируйте **сразу всю пачку** в `content/blog/`. Можно использовать вложенные папки, например `content/blog/2026/oktyabr/`.
3. В терминале из корня проекта выполните:

   ```powershell
   npm run blog:check
   ```

4. Откройте `/blog` и обновите страницу. Список, темы, поиск, отдельные страницы статей и содержание создаются автоматически. Вручную менять код или список статей не нужно.

**Локально** при запущенном `npm run dev` изменения видны после обновления страницы. **На работающем Node-сервере** с `npm run start` новые `.md` в папке `content/blog` подхватываются в течение **10 секунд**, без перезапуска приложения. Уже открытая вкладка сама не перезагружается: обновите её.

Если сайт публикуется через сборку из Git и файлы сервера нельзя изменять напрямую, после добавления статей отправьте изменения в репозиторий и запустите обычный деплой. Копирование файлов на ваш компьютер само по себе не обновляет удалённый сайт.

## Пример готового файла

Создайте файл `content/blog/kak-vybrat-sayt.md`:

```markdown
---
title: "Как выбрать сайт для своего дела"
description: "Короткое описание для списка статей и поисковых систем."
date: "2026-10-25"
slug: "kak-vybrat-sayt"
category: "Выбор сайта"
tags: ["сайт", "малый бизнес"]
draft: false
---

Вступление. Объясните, какую задачу читателя решает статья.

## С чего начать

Основной текст. Важное можно выделять **жирным**.

## Что проверить

- Первый пункт.
- Второй пункт.

## Следующий шаг

[Посмотреть готовые дизайны](/catalog)
```

Статья появится по адресу `/blog/kak-vybrat-sayt`.

В проекте есть заготовка `content/blog/_template.md`. Скопируйте её, переименуйте файл, замените поля и текст, установите `draft: false`. Сам файл `_template.md` игнорируется и на сайте не появляется.

## Что означают поля

| Поле | Обязательно | Как заполнить |
| --- | --- | --- |
| `title` | Да | Заголовок статьи, до 140 символов. |
| `date` | Да | Существующая дата в кавычках: `"2026-10-25"`. Новые даты идут первыми. |
| `description` | Нет | Короткое описание, до 300 символов. Если не указано, берётся начало текста. |
| `slug` | Нет | Адрес: строчные латинские буквы, цифры и дефисы. Должен быть уникальным во всём блоге. |
| `category` | Нет | Тема статьи. Новая тема автоматически появится в фильтре. По умолчанию — «О сайтах». |
| `tags` | Нет | Ключевые слова для поиска: `["тексты", "дизайн"]`, до 12 тегов. |
| `draft` | Нет | `true` скрывает статью. `false` или отсутствие поля публикует её. Без кавычек. |

Если `slug` не указан, адрес строится из имени файла. Например, `Как выбрать сайт.md` превратится в `/blog/kak-vybrat-sayt`. Для постоянных ссылок лучше указывать `slug` явно: тогда файл можно переименовать без изменения адреса.

Вложенные папки помогают вам хранить материалы, но не добавляют уровни в адрес. `2026/article.md` и `guides/article.md` получат одинаковый адрес без явного `slug` — проверка сообщит о конфликте. Задайте уникальные значения.

Поле `date` используется для отображения и сортировки, **это не отложенная публикация**. Для ещё не готовой статьи используйте `draft: true`. Черновики недоступны и по прямому адресу, и в карте сайта.

## Пакетное добавление

Можно перетащить в `content/blog` десятки файлов или целую папку. Пример структуры:

```text
content/blog/
  _template.md
  vybor-sayta/
    gotovyy-dizayn.md
    landing-ili-vizitka.md
  teksty/
    zagolovok.md
    opisanie-uslug.md
```

Проверить внешнюю папку **до копирования** можно командой:

```powershell
npm run blog:check -- "D:\Статьи\Готовые"
```

После копирования обязательно проверьте весь блог командой `npm run blog:check`: она дополнительно обнаружит совпадения адресов с уже существующими статьями.

Файлы и папки, начинающиеся с `_` или `.`, игнорируются. Допустимы расширения `.md` и `.MD`. Максимальный размер одного файла — 2 МБ; изображения храните отдельно.

При массовом обновлении работающего сервера сначала загрузите готовые файлы в отдельную папку, проверьте их, а затем перенесите в `content/blog`. Так посетители не увидят промежуточное состояние незаконченной загрузки.

## Оформление текста

Заголовок `title` сайт выводит сам. Основной текст удобно начинать с абзаца, а разделы — с `##` и `###`. Содержание справа собирается из этих разделов автоматически. На телефоне оно находится перед текстом и сворачивается.

Поддерживаются:

- абзацы, жирный и курсивный текст;
- маркированные и нумерованные списки;
- списки задач: `- [ ] Проверить` и `- [x] Готово`;
- таблицы Markdown;
- цитаты с `>`;
- блоки кода в тройных обратных кавычках;
- ссылки и изображения;
- сноски.

HTML, скрипты, JSX и MDX не исполняются. Используйте обычный Markdown. Ссылки на страницы сайта пишите от корня: `[Каталог](/catalog)` или `[Другая статья](/blog/slug-stati)`, а не на локальный `.md`-файл.

Для изображения положите файл, например, в `public/blog/example.jpg` и вставьте:

```markdown
![Описание изображения](/blog/example.jpg)
```

Новые изображения из `public` публикуйте вместе с обычным обновлением сборки сайта. Обещание подхвата без перезапуска относится к `.md` в `content/blog`; файлы `public` управляются самим Next.js.

## Изменение и удаление

- Чтобы исправить текст, отредактируйте тот же `.md`.
- Чтобы временно убрать статью, поставьте `draft: true`.
- Чтобы удалить статью, удалите её `.md`.
- Сохраняйте прежний `slug`, если не хотите менять ссылку. Автоматических перенаправлений со старого адреса нет.

На обычном сервере изменения вступят в силу после обновления кеша, максимум через 10 секунд. На хостинге со сборками требуется новый деплой. Удалённая или скрытая статья возвращает 404.

## Если статья не появилась

Выполните `npm run blog:check`. Команда покажет имя проблемного файла и причину: нет `title` или `date`, ошибка YAML, повторяющийся `slug`, неправильный тип поля и т. п.

Некорректные файлы пропускаются при чтении работающего сайта, чтобы одна ошибка не сломала весь блог. При конфликте `slug` скрываются все статьи с этим адресом до исправления. Перед production-сборкой проверка запускается автоматически и останавливает сборку при ошибках.

Также проверьте `draft`, имя файла (без `_` в начале), кодировку UTF-8 и папку, в которой запущен сервер. Рабочая директория сервера должна содержать `content/blog`.

## Публикация через Git

После добавления и проверки статей:

```powershell
git add content/blog
git commit -m "Add blog articles"
git push
```

Если на хостинге настроен автоматический деплой из Git, он подхватит изменения. Иначе выполните обычную публикацию новой версии. `npm run build` автоматически проверяет статьи; `npm run start` запускает собранный сайт.

При самостоятельном размещении на Node-сервере можно вместо сборки загружать только `.md` в `content/blog` через ваш файловый доступ. В среде с несколькими серверами у всех экземпляров должна быть одинаковая папка статей. При неизменяемой файловой системе используйте деплой.

## Что автоматизировано

В блоге есть поиск по заголовку, описанию и тегам, фильтр по теме, сортировка по дате и страницы по 12 статей. На странице статьи автоматически создаются содержание, время чтения и SEO-описание. Статьи включаются в sitemap, когда в проекте включена production-индексация. Общая настройка деморежима сайта сохранена.

Для большого количества файлов чтение ограничено 16 одновременными операциями. Неизменившиеся файлы не разбираются повторно; HTML создаётся только для открываемых статей, а кеш HTML ограничен 64 записями. Все статьи не отправляются в браузер одним пакетом.
